La Reserva Naturaleza Arte

lareserva.net.ar

A 250 hectare retreat property in Capilla del Senor, Buenos Aires. The site does three jobs: show the place, publish the agenda of retreats, and capture enquiries. Everything else in here exists to serve one of those three.

There is no CMS, no framework and no build step. It is PHP talking to MySQL, rendering HTML, with vanilla JavaScript on top. Files are uploaded by hand through cPanel File Manager. That constraint shaped every decision below, and it is worth understanding before changing anything.

The one thing to internalise: this site has two separate tracking ideas that look similar and are not. ref is where a visitor came from. boton is what they clicked once they arrived. Mixing them destroys the reporting. See ref vs boton.

Public page

espacios.php

A card per space. The card shows a photo by default and plays its video only while the pointer is over it. Clicking opens a lightbox: media carousel on the left, everything else on the right.

What the lightbox panel holds

  1. Badge, name, description, capacity
  2. Upcoming retreats on the property
  3. Occupancy calendar with month arrows
  4. Enquiry form writing to consultas
  5. WhatsApp button and Instagram link

The calendar is a range picker

First tap sets the start, second sets the end, tapping the start again clears it. The range is written to fecha_tentativa and fecha_fin, and spelled out above the form as "Del 10 de noviembre al 13 de noviembre (3 noches)".

A range cannot cross a booked day. Once a start is picked, any day whose path back to that start crosses an occupied day is greyed and struck through. Nobody can request 14 to 20 September when the 17th already has a retreat, so you never receive an enquiry you have to turn down.
The calendar shows property-wide occupancy, not this space. The retiros table has no espacio_id column, so there is nothing to filter on. The label says "Fechas ocupadas en el predio" for exactly this reason. The same gap is why every space lists all upcoming retreats under "Próximos retiros en este espacio". Fixing it means adding espacio_id to retiros plus a dropdown in the panel.
Public page

retiros.php

The agenda. Each row is a real link to retiro.php?r=slug, intercepted by JavaScript to open a lightbox instead. If the JS payload has no entry for that id the handler returns true and the link goes through, so crawlers and no-JS visitors are unaffected.

The RSVP endpoint

The same file answers its own form. A POST with accion=rsvp returns JSON and exits before any HTML, so the lightbox stays open while the row is written.

retiros.phprsvp flow
POST accion=rsvp
  honeypot filled?        -> pretend success, write nothing
  CSRF token bad?         -> "La sesion expiro"
  IP on ip_bloqueadas?    -> generic failure, no detail leaked
  over 5 posts per hour?  -> ask them to wait
  email disposable?       -> reject, log rsvp_rechazado
  otherwise               -> INSERT consultas, log rsvp_ok

It shows the retreat's own dates and is deliberately not a picker. You book the encounter, not individual nights, and the caption underneath says so.

Inbox

Reads the mensajes table, filled by a mail pipe. Read only: Reply opens your own mail client rather than calling mail(), because a reply that silently vanishes is worse than no button. The original always stays in webmail. Attachments are counted, never stored.

Writing uploaded files to disk from unauthenticated senders is the single most dangerous thing this codebase could do. It is deliberately not done.

Consultas

Every enquiry from every form. Filter by estado, change estado, add internal notes.

This page is load bearing for the reports. "Concretadas" on the Referidos page counts enquiries whose estado you moved to coordinada or cerrada. If everything stays on nueva, every referrer and every button shows zero conversions forever. That is the manual work the reporting costs you.

Referidos

Three tables on one page.

  • Codigos per referrer or channel: aperturas, consultas, concretadas, conversion, WhatsApp clicks, total paid. Direct traffic appears as its own row.
  • Codigos vistos sin registrar: traffic that arrived with a ?ref= matching no code. Usually a typo in a shared link.
  • Botones del sitio: clicks per button, with consultas and concretadas.

Opening a code gives four ready made links to copy, for agenda, espacios, inicio and galeria.

Nothing computes money. The system has no payment data: an enquiry is an enquiry, precio_desde is a starting price nobody has paid, and space enquiries carry no price. Commission is a text note you agreed with the person, and the payout table is a ledger of what you already paid. A calculated "owed" figure would look authoritative and be fiction.

Trafico y seguridad

Event counters over 7, 30, 90 or 365 days. Conversion per retreat. Breakdown per ref. Most active IPs with a one click block. The blocked list. The last 60 raw events. A purge button for events older than 180 days.

IP blocking is weaker than it sounds. Argentine domestic IPs rotate and a VPN defeats it in one click. It stops a repeat bot, not a determined person. The disposable email check and the honeypot do more work than the IP list ever will.

Read this twice

ref vs boton

Two questions that sound like one. Keeping them apart is the difference between a report you can act on and a report that lies to you.

ref

Where the visitor came from. Set once on arrival from ?ref= or ?utm_source=, lowercased, kept in the session for the whole visit. Anyone with no code is tagged directo.

boton

What they clicked once they were here. Baked into the page, so it counts without anyone sharing a link. Recorded on the event and on the enquiry.

Why they cannot be the same field. If clicking "Solicitar lugar" set ref=lr, then a visitor who arrived from your WhatsApp status would be relabelled at the moment they book. Every booking would be credited to lr, and whatsapp, instagram and johnny would all show clicks with zero conversions, forever. The one number worth having becomes unreadable.
a real rowboth facts survive
Visitor clicks your Instagram bio link
  ?ref=instagram           -> session ref = instagram
Browses, opens Main Hall
  event abrir_espacio        ref=instagram  boton=(none)
Fills the form, clicks Solicitar fecha
  event consulta_esp_ok      ref=instagram  boton=lr
  consulta                   ref=instagram  boton=lr

Reads as: Instagram brought them, the form converted them.

How a click is recorded

includes/footer.phpone helper, every page
lrBoton('click_wa', 'whatsapp', 'Summer Retreat 2027')
  -> navigator.sendBeacon('track.php', {...})
  -> falls back to fetch(keepalive) on old browsers
  -> never blocks or delays the click
sendBeacon is the reason a WhatsApp or Instagram click still counts. A normal fetch is cancelled when the browser navigates away. A beacon is handed to the OS and survives.
track.php only accepts event types on its whitelist. Anything else is dropped silently. Adding a new event type means adding it there too, or it will look like the tracking is broken when it is actually working exactly as designed.

Mail into the panel

A PHP page cannot receive email. It can only read mail already delivered somewhere. On cPanel with no SSH there is one clean route.

Step 1

The mailbox

johnny@lareserva.net.ar, created in cPanel. Real mailbox, real webmail, real storage.

Step 2

The pipe script

/home/lareserv/pipe_correo.php, chmod 755, outside public_html. Exim hands it the raw message on stdin. It unfolds headers, decodes MIME encoded subjects, walks multipart bodies preferring text/plain, counts attachments, and writes one row into mensajes.

It always exits 0. A non-zero exit makes Exim bounce the message back to the sender, so a bug in the parser must never become a bounce in front of a customer. Failures go to /home/lareserv/pipe_correo.log instead.
Step 3

The Exim filter

cPanel > Email > Email Filters, not Forwarders and not Roundcube's own filters. Two actions, both required:

Inbox al panelorder matters
Rule    To  contains  johnny@lareserva.net.ar

Action  Deliver to folder    INBOX
Action  Pipe to a Program    $home/pipe_correo.php

Without the first action, mail stops arriving in webmail. The pipe path must be $home/pipe_correo.php or an absolute path. A bare relative filename is not resolved against your home directory and the script silently never runs.

Diagnosing it: no pipe_correo.log at all means the pipe never executed, which is a path or permissions problem. A log with lines in it means PHP ran and hit something, and the line names it.

There is an allowlist mode and it should stay off. LR_SOLO_PROVEEDORES_CONOCIDOS restricts to Gmail, Outlook, Yahoo, iCloud and Proton. Turn it on and every facilitator with a custom domain, every corporate organiser and every agency is rejected. Those are the highest value enquiries. Blocking throwaway domains is the right shape; allowlisting the big five is not.
Every check fails open if its table is missing. A broken log must never block a real booking.

Uploads

TypeDirectory
Imagesassets/img/galeria/
Videosassets/video/pages/
Page heroesassets/video/hero.mp4, assets/video/pages/*.mp4

File inputs must be named imagen and video. Only one is enabled at a time; the other is disabled so it drops out of the request. mime_content_type() works on this server and must not be swapped for extension checks. No mkdir() in upload handlers.

The limits are set in .htaccess

public_html/.htaccess.user.ini is ignored on this account
<IfModule lsapi_module>
  php_value upload_max_filesize 180M
  php_value post_max_size       210M
  php_value memory_limit        256M
</IfModule>
The forms read the live limit from PHP and refuse an oversized file in the browser, with the real figure in the message. If the body ever does exceed post_max_size, the handler detects the discarded POST and says so instead of blaming the session.

Hard rules

  • No em dashes anywhere. Plain hyphen only, in code and in copy.
  • No references to AI tools in code or comments.
  • Version markers in filenames and in an HTML comment. With no SSH it is the only way to confirm what is deployed.
  • From-scratch rewrites over patches when a file has accumulated too many fixes.
  • Never open Sitejet in cPanel. It overwrites files.
  • Delete generar-hash.php immediately after use.
  • Nav uses id selectors, never classes. Classes collide with cached CSS.
  • Check consultas, not email. mail() is unreliable here.
  • DB_PASS is the MySQL password, not a bcrypt hash.
Post mortem

What broke and why

Six bugs that cost real time. Each one is worth reading because the same class of mistake will happen again.

Bug 1

Every form said "La sesión expiró"

Not a session problem. csrfToken() started the session lazily, and on public pages it was first called in the middle of the HTML. By then the headers were gone, session_start() could not send the cookie, and the token was never stored. The browser posted a token the server had no record of.

Fix: start the session at the top of config.php, before any output. Admin pages were never affected because exigirSesion() runs on line 2.

Evidence it was that: consultas had zero rows. Not one message had ever been stored, from any form, since launch.

Bug 2

admin/retiros.php returned 500 on every request

A parse error, not an upload bug. if ($accion === 'guardar') { was never closed, so the following elseif landed inside its body. A stray extra brace further down made the total count balance, which is why a brace counter passed and told us nothing.

Lesson: balanced braces are not valid syntax. Run php -l. A counting heuristic gives false confidence.
Bug 3

Video uploads over 5MB said "Sesion expirada"

PHP discards $_POST and $_FILES together when the body exceeds post_max_size. With no accion field the CSRF bypass never triggered, so the code blamed the session. The real limit was 8M / 2M: .user.ini was being ignored entirely.

Fix: the limits moved to .htaccess, and the handler now detects a discarded POST and reports the actual size against the actual limit.

A related false lead: "media.php uploads 86MB files fine". It does not. That screen shows filesize() of a file already on disk, put there by File Manager. Reading a UI label as evidence of a code path cost an hour.
Bug 4

The espacios lightbox could not be scrolled

The panel is a CSS grid item. Grid items default to min-height:auto and refuse to shrink below their content, and max-height caps the box but not the row. So the row grew to full content height, overflow:hidden clipped it, and the panel had no overflow of its own to scroll.

Fix: grid-template-rows: minmax(0, 1fr) plus a definite box height. min-height:0 alone, tried first, changed nothing.

Bug 5

The mail pipe never ran

No pipe_correo.log at all, which meant PHP never started. Not the shebang: all eight PHP binaries on the server worked when tested directly. The filter's pipe path was a bare relative filename, which Exim does not resolve against the home directory.

Fix: $home/pipe_correo.php.

Bug 6

"directo" was reported as an unregistered code

Self inflicted. config.php assigns directo to visitors with no code, then the referidos page compared every seen code against the registered list and flagged it as an orphan.

Fix: it gets its own row and is excluded from the orphan check.

Runbook

A form says the session expired

  1. Check the browser has a PHPSESSID cookie for lareserva.net.ar
  2. If not, config.php is not starting the session before output. Check its version marker

An upload fails

  1. Open admin/diag.php and read the local value of post_max_size
  2. If it is 8M, the .htaccess block is missing or the handler ignores php_value
  3. Fall back to cPanel > MultiPHP INI Editor

A page returns a blank 500

  1. Read /home/lareserv/logs/php.error.log. It is always there
  2. A blank 500 with no visible error is almost always a parse error, which happens before display_errors can be set
  3. display_errors must be set after the require, because config.php turns it off at the bottom

Mail is not reaching the panel

  1. Does it reach webmail? If not, it is DNS or MX, not the code
  2. Does /home/lareserv/pipe_correo.log exist? No file means the pipe never executed
  3. Check the filter's pipe path and that the script is 755
  4. cPanel > Metrics > Track Delivery shows Exim's actual result per message

The referral report shows zero conversions

Almost certainly correct. "Concretadas" counts enquiries moved to coordinada or cerrada in the Consultas inbox. If everything is still nueva, the answer is zero and the code is fine.
