La Reserva Naturaleza Arte

Sitio y panel de administracion de lareserva.net.ar, un predio de 250 hectareas en Capilla del Senor, Buenos Aires, donde se organizan retiros y encuentros.

PHP 8.1 + MySQL + JavaScript sin frameworks. Sin composer, sin npm, sin build. Los archivos se suben a mano por cPanel File Manager.

Antes de tocar nada

includes/config.php no esta en el repositorio y no tiene que estar nunca. Tiene la password de MySQL. Esta en .gitignore. Si alguna vez aparece en un commit, cambia la password de la base antes de hacer cualquier otra cosa: una vez que entro al historial de git, sigue ahi aunque borres el archivo.

Para arrancar:

cp includes/config.example.php includes/config.php
# completar DB_PASS y el resto de los valores

DB_PASS es la password de MySQL, no un hash bcrypt. El hash vive en la tabla usuarios y sirve para el login del panel, que es otra cosa.

ref y boton son dos cosas distintas

Es lo unico de este proyecto que conviene entender antes de tocar el codigo.

  • ref es de donde vino la persona. Se fija una sola vez al llegar, desde

?ref= o ?utm_source=, y queda en la sesion toda la visita. Quien llega sin codigo queda como directo.

  • boton es que toco una vez adentro. Va escrito en la pagina, asi que

cuenta sin que nadie comparta ningun link.

Si se pisan, se pierde la atribucion: todas las reservas quedarian acreditadas al boton y los canales mostrarian clicks con cero conversiones para siempre.

Reglas del proyecto

  • Nada de rayas largas. Guion comun, en codigo y en texto visible.
  • Version en el nombre del archivo y en un comentario HTML. Sin SSH es la

unica forma de confirmar que hay en el servidor. Ctrl+U y buscar <!-- espacios.php VERSION 2.8 -->.

  • Reescribir de cero antes que parchear un archivo que ya acumulo demasiados

arreglos.

  • No abrir Sitejet en cPanel. Sobreescribe los archivos del sitio.
  • mail() no es confiable en este hosting. Las consultas se revisan en

admin/consultas.php, nunca por correo.

  • El nav usa selectores por id, nunca clases. Las clases chocan con el CSS

cacheado.

  • display_errors se define despues del require, porque config.php lo

apaga al final.

  • Nada de mkdir() en los handlers de subida. Solo directorios que ya existen.
  • Borrar del servidor generar-hash.php, admin/diag.php, admin/pipe_test.php

y admin/upload_test.php apenas dejan de hacer falta.

Trampas conocidas

SintomaCausa real
Todos los formularios dicen "La sesion expiro"La sesion arranca despues de que salio HTML, la cookie nunca se envia
500 en blancoError de sintaxis: pasa antes de que display_errors pueda activarse
"Sesion expirada" al subir un video grandeEl body supero post_max_size, PHP tira $_POST y $_FILES juntos
Un panel en grid no scrolleaLos grid items son min-height:auto; hace falta minmax(0,1fr) en la fila
El pipe de correo no correLa ruta relativa no se resuelve contra el home. Usar $home/pipe_correo.php
mime_content_type() indefinidoSe cayo la extension fileinfo. Usar lrMime() de config.php
Llaves balanceadas pero igual rompeContar llaves no valida sintaxis. Correr php -l

Subir cambios

No hay pipeline. El repositorio es historial y respaldo, no destino de deploy.

  1. Editar, probar en local si se puede
  2. Subir el archivo por cPanel File Manager
  3. Ctrl+U y confirmar el marcador de version
  4. Commitear con un mensaje que diga que cambio y por que
